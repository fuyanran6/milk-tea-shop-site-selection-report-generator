一、第一优先级：先修数据一致性问题，修完以后再优化视觉
当前报告已经出现明显的数据逻辑冲突，例如：
300m 茶饮数量 &gt; 500m 茶饮数量
300m 餐饮数量 &gt; 500m 餐饮数量
已知候选点距离地铁站约80m，但交通查询结果却显示1000m内无地铁/公交
这些情况不能继续进入评分和最终报告。
请增加一个独立的 data_validation / evidence_validation 层。
请你修正这种问题，增加以下校验：
1. 嵌套半径一致性
对于同一种 POI 分类：
count_300m &lt;= count_500m &lt;= count_1000m
2. 交通一致性
现在如果候选地址文本或地理编码结果明确存在附近地铁站，但交通 API 查询出现结果为空的情况：
触发交通数据异常
检查查询 category / radius / 分页 / API 参数
3. POI 分类污染检查
不要简单把地图搜索结果全部视为“奶茶竞品”。
将竞争对象拆分为：
DIRECT_TEA
奶茶、茶饮、柠檬茶等直接竞品
INDIRECT_BEVERAGE
咖啡、果汁、其他即时饮品
FOOD_COMPLEMENT
快餐、正餐、餐饮配套
NON_COMPETITOR
与茶饮消费决策关系较弱的业态
严格禁止“必胜客、CoCo壱番屋”等普通餐饮被统计为奶茶竞品。
4. 连锁识别
维护可配置的品牌名单或标准化品牌字段。
